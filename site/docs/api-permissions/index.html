Permissions

Who may do what in Markstage, by role: owner, administrator, editor, author and contributor, the WordPress names, decided in one place on the server.

Part of the API contract (docs/API.md: its conventions, prefix and errors apply here). Who may do what, by role (owner, administrator, editor, author, contributor, the WordPress names). Every decision is made in one file, packages/server/src/roles.mjs; this table is its human-readable copy and changes with it.

A person with a custom role (docs/API-ROLES.md) has its base as their role in this table; the role's own rules come first: a rule that denies takes a right away, one that allows gives a right the base lacks (never one that is "yes" only for the owner and administrators here).

"Own" = the entry's author field equals the user's authorSlug. Authors and contributors always create entries under their own authorSlug. "Raw HTML" = blocks the converter could not map to a known node or block pack (core rawHtmlOf(doc): block rawHtml {html} and inline rawInline {html}); a contributor's save may keep the ones already there but not add or change any (403).

An AI assistant reads more narrowly than a person in the editor does: an author's or a contributor's token shows live entries and their own drafts only, and so do the pages a Library item lists and a release's entries; plans, which name every file they move, are for editors and up. A person reads a colleague's draft in the editor to work on it with them. An agent copies what it reads into a model's context, where it can travel further, so it gets only what its person needs (docs/API-MCP.md "Reads follow the role").

Source: docs/API-PERMISSIONS.md on GitHub. Something unclear? Open an issue.
