Strapi is a widely used headless CMS that you run yourself or on Strapi Cloud, with REST and GraphQL APIs. Astro reads it through a small wrapper. Markstage is an editor for an Astro site's own Markdown and JSON files in git.

Who each one is for

Strapi suits teams who want a self-hosted content API for several front ends, with a customisable admin and a large community.

Markstage suits an Astro content site whose writers should edit on the real design, with no separate content API. Markstage is pre-release.

Where Strapi is stronger

  • A content API for many front ends and apps.
  • A very large community (about 73k GitHub stars on 3 November 2026).
  • Strapi Cloud if you want it hosted.

Moving from Strapi to Markstage

Read your entries through Strapi's API, convert rich text to Markdown, and run Markstage's import API (dry run first, imported as drafts, idempotent on each source id).

Frequently asked questions

Does Strapi work with Astro?

Yes. Astro's docs have a Strapi guide that builds a wrapper function to fetch from Strapi.

Which Strapi plans include Live Preview and Releases?

On 3 November 2026 Strapi's docs listed Live Preview and Releases on the Growth and Enterprise plans.

Is there a Strapi alternative without a database?

Markstage keeps content in git and needs no database server. One SQLite file on its server holds people, sessions, the inbox, drafts in progress, trash, releases, the media index and the audit log.
