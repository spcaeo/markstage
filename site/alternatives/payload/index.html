Payload is a Next.js-native headless CMS and application framework, with a database (MongoDB, Postgres or SQLite), very granular access control and Live Preview. With Astro, it is a separate backend that your site reads. Markstage is narrower: an editor for an Astro site's Markdown and JSON files in git.

Who each one is for

Payload suits developers building an application, a shop or a content backend that needs custom code, a database and fine access control, often with Next.js.

Markstage suits an Astro content site whose writers should edit on the real design, with no application backend to build. Markstage is pre-release.

Where Payload is stronger

  • A full backend: your own collections, hooks, APIs and access control, in code.
  • Apps and shops, not only content sites.
  • A very large community (about 45.6k GitHub stars on 3 November 2026).

Moving from Payload to Markstage

For a content site, export your documents through Payload's API, convert rich text to Markdown, and run Markstage's import API (dry run first, imported as drafts, idempotent on each source id). Keep Payload if the same backend also runs an app.

Frequently asked questions

Does Payload work with Astro?

Yes, as a headless source: Astro's docs have a Payload guide and link an official example project.

Is Payload free?

Its repository is under the MIT licence. Some features (a visual editor, publishing workflows, SSO) are listed as Enterprise features.

When is Markstage the better fit?

When the site is an Astro content site, the team wants content as files in git, and nobody wants to run an application backend and database for it.
