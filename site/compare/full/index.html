The short answer

  • Astro has no editor of its own. Its docs describe a CMS as a separate tool that "lets you write content and manage assets outside of your Astro project", and list 45 of them 1. Content collections give Markdown, MDX, YAML and JSON files a schema and type safety, but no screen for a writer 2.
  • Markstage is for a team that wants all of these at once: writers edit on the site's own design; a save changes only what was edited (a clean git diff) and, with the Markstage server, is committed as the person who saved; no database server holds the content; staging and release rules are included; and it all runs on your own server for free.
  • WordPress, Ghost and Prismic are the three people weigh most often. WordPress and Ghost are mature publishing platforms with large communities; with Astro, both are used headless (Astro reads their content by API, and writers work in their own admin). Prismic is a hosted page builder. The next section puts the three side by side with Markstage.
  • The closest products are CloudCannon (git-based, edits on a preview of your built site, hosted only, from $55 a month), TinaCMS (git-based, click-to-edit on Astro pages, hosted or self-hosted), and Storyblok, Sanity and Prismic (visual editing on a hosted content database).

How to choose among these four:

  • WordPress if you want its very large ecosystem of themes, plugins, hosts and people who know it, or a familiar admin for content that Astro reads by API.
  • Ghost if the site is a publication: newsletters, memberships and paid subscriptions are built in 95, with its own editor and themes, self-hosted or on Ghost(Pro). Its code is under the MIT licence 93.
  • Prismic if you want a hosted page builder with nothing to run, and your developers build the sections ("slices") 69.
  • Markstage if writers should edit on the Astro site's own design, content should stay as files in git, and staging, roles and single sign-on should come included on your own server. Markstage is pre-release; WordPress and Ghost have many years of production use and much larger communities.

Where Markstage leads

Each line names the capability and which of the 21 products above have it, as checked on 2026-11-03 (Ghost on 2026-11-04).

  1. Editing on the site's own design, from your own server, with no database server. Of the 21 products, those that edit on the real page are TinaCMS, CloudCannon, Storyblok, Sanity and Builder.io; Decap CMS, Sveltia CMS, Front Matter, Prismic, Payload, Strapi, Statamic and EmDash do it partly (a preview beside a form, or on some plans). Of those, CloudCannon, Storyblok, Sanity and Builder.io are hosted services, and self-hosted TinaCMS needs a database adapter as a cache. Markstage keeps content in git and its own working data (people, sessions, the inbox, drafts in progress, releases) in one SQLite file.
  2. The live site stays static. Markstage's editor markup appears only in editor mode, so the production build is byte-identical 4. TinaCMS visual editing wants server output or <TinaIsland> wrappers, Keystatic keeps pages static but needs an adapter for its admin routes, and EmDash and StudioCMS run the site as a server.
  3. Staging and production for content and code together, free. A promotion is a git merge, so templates, models and chosen pages move together, and content syncs back down by merge, not by overwrite 7. Storyblok and Prismic sell environments on their top plans, Sanity charges $999 a month per extra dataset, and CloudCannon has branch sites on its Team plan ($350 a month).
  4. Surgical saves. Opening and saving changes nothing; a save rewrites only the changed blocks (a clean git diff) and, with the Markstage server, is committed as the person who saved 6. JSON written by Keystatic stays byte-identical when Markstage saves it.
  5. A site's back office in one tool. Forms inbox, media, menus, moved addresses, translations status, SEO checks, releases with share links, backups and rollback, single sign-on and custom roles, all included 3 12 11 10. Among the git-based editors only CloudCannon also has a forms inbox.

Where others go further

  • Hosted, nothing to run. CloudCannon, TinaCloud, Storyblok, Prismic, Sanity, Contentful and Builder.io run everything for you, and Ghost(Pro) hosts Ghost 94. Markstage needs a server you look after.
  • Newsletters and paid memberships. Ghost has newsletters, memberships and paid subscriptions built in 95. Markstage has none of these.
  • No server at all. Decap CMS and Sveltia CMS are a single page that talks to your git host; Front Matter runs inside VS Code. Markstage needs Node and git on a server.
  • MDX. TinaCMS, Keystatic and Outstatic edit MDX and have done so for longer. Markstage's MDX support is new: it edits the words and a component's simple settings, keeps the code as written, and shows components as cards on the canvas rather than as the site renders them 5.
  • Live co-editing. Sanity's real-time content database and Sitepins' live cursors let people edit together. Markstage uses locks and a three-way merge.
  • Size and age. WordPress and Ghost are mature publishing platforms used by very many sites. Strapi (73.4k GitHub stars), Ghost (55.7k), Payload (45.6k), Decap CMS (19.4k), EmDash (14.1k) and TinaCMS (13.9k) have large communities 105. WordPress, Contentful and Sanity have big partner and plugin ecosystems, and Ghost has a theme marketplace 94. Markstage is pre-release.
  • Other frameworks. Most products here also serve Next.js, Hugo, Eleventy and others. Markstage has one adapter today, Astro; adapters beyond Astro are on its roadmap.
